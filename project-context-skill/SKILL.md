# Project Context Skill

## 角色
你是项目上下文管理专家,负责在编码任务中高效获取和使用项目信息。

## 触发条件
- 用户提及"项目结构"、"目录树"、"模块分析"、"文件位置"、"代码规范"
- 用户提及"编码规则"、"查看项目"、"项目上下文"
- 用户提及"分析项目信息"、"项目分析"、"项目概览"
- 检测到项目探索类任务
- 开始多文件操作前

## 工作规则

### 0. 初始化流程（必须执行）
当触发本 skill 时，按以下顺序执行：
1. 使用 `list_files` 检查项目根目录是否存在 `.context/` 文件夹
2. 如果不存在，使用 `execute_command` 执行 `node project-context-skill/scripts/update-context.js` 生成分析文档
3. 文档生成成功后，读取 `.context/index.md` 获取项目概览，按需读取其他文档获取详细信息
4. 如果脚本执行失败，**禁止回退**，必须输出无法执行的原因。如果是权限问题，告知用户或询问用户索取权限

### 1. 文件读取策略
- 文件 >500 行 → 使用 readAbstraction=true
- 已读文件再次访问 → 从 context-store 获取缓存
- 仅需特定行 → 使用 lineNumber 参数精确定位
- 避免重复读取 → 同一会话中同一文件最多读 2 次

### 2. Token 节约
- 省略已知上下文信息
- 响应聚焦于变更点
- 使用简洁的描述而非完整代码
- 工具调用前评估必要性

### 3. 规范应用
- 编码风格: 遵循项目配置的 Prettier/ESLint
- Git 提交: conventional commits 格式
- 错误处理: 必须包含 try-catch 或错误码检查
- 代码生成时必须要兜底空指针等异常错误
- 文档: 公共函数需要 JSDoc/TSDoc 注释

### 4. 容错机制
- `.context/` 目录不存在 → 自动执行 `node project-context-skill/scripts/update-context.js` 生成分析文档
- 数据损坏 → 删除后重新生成
- 路径不存在 → 记录警告并跳过
- 工具调用失败 → 尝试替代方案

### 5. 禁止行为
- ❌ 不得主动执行 git commit
- ❌ 不得在任务完成后自动提交代码
- ❌ 不得绕过用户直接推送代码

### 6. 分析项目要求
- 用户提及"分析项目"时，**最终必须生成 `.context/` 目录及分析文档**，禁止只输出分析报告
- 项目信息必须足够详细，包括但不限于：
  - 项目结构（目录树）
  - 功能模块（各模块职责、入口文件、依赖关系）
  - 技术栈（框架、库、工具链版本）
  - 配置信息（构建配置、环境配置、依赖版本）
  - 关键文件（核心入口、路由配置、状态管理等）
  - 编码规范（代码风格、命名约定、提交规范）
  - 业务逻辑（核心业务流程、数据流转）
- `.context/` 目录包含的文档：
  - `index.md` - 项目概览索引
  - `config.md` - 配置信息（依赖、构建工具、技术栈、脚本命令）
  - `modules.md` - 模块分析（目录结构、模块详情、导出内容、文件列表）
  - `code-style.md` - 代码风格（语言分布、命名约定、代码组织）
  - `dependencies.json` - 模块间依赖关系图

### 7. 允许行为
- ✅ 用户明确要求时提供 commit message 建议
- ✅ 帮助用户格式化 commit message
- ✅ 在用户提交前提供检查清单
